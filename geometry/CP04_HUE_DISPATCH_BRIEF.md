# Decision brief — hue_pair canonical dispatch (owner call)

Date: 2026-11-27 · Agent: jjcav84/Devin · Status: **recommend DEFER**
Context: Recursiverse GOV-005 protects `artifacts/coordinate_envelope.py`
+ `tests/test_coordinate_envelope.py`. Amendment A1 allows *additive*
files under `artifacts/geometry_ir/` + `tests/geometry_ir/` only.
`hue_pair` currently lives additively in
`artifacts/geometry_ir/hue_pair.py` (`convert_hue_pair`, `apply_hue_op`);
the frozen `convert()` dispatcher rejects it (`frame not in FRAMES`).

## The question

Should `coordinate_envelope.convert()` route `hue_pair` — i.e., amend
the protected file (FRAMES + dispatch branch) under a new GOV-005
carve-out — or should hue_pair remain additive indefinitely?

## What each option actually means

| Option | Change | Governance cost | Effect |
|---|---|---|---|
| **1. Amend dispatch** | Add `"hue_pair"` to `FRAMES` + branch delegating to `convert_hue_pair` logic; CONSTITUTION carve-out for modification (not just addition) | **High** — first modification-amendment to a GOV-005 file; sets precedent that protected files can be amended | `convert(env, anchor)` becomes total over all contract frames; Recursiverse-internal ergonomics only |
| **2. Stay additive** | None — status quo | Zero | Callers `from artifacts.geometry_ir.hue_pair import convert_hue_pair`; explicit is arguably better (hue semantics visibly separate from position frames) |
| **3. Status-quo + doc** | Add a comment/doc note in `hue_pair.py` (additive path, allowed) stating dispatch is deferred pending production adoption | Zero | Same as 2, with the decision recorded at point of use |

## What it does NOT affect

- **Interchange conformance is identical under all options.** The CP-04
  fixture's 144 `expected_cancer` values are generated by
  `convert_hue_pair`, and all three consumers (Recursiverse additive
  module, z12z `convert_hue_pair`, Machine `hue_pair_to_machine`)
  implement against the *fixture contract*, not against `convert()`.
- The adoption-depth audit (CP04_ADOPTION_DEPTH.md) found **zero
  production callers** of the hue path anywhere — the dispatch question
  is currently about API ergonomics for callers that do not exist.

## Recommendation: DEFER (option 3 now, revisit on first production caller)

1. No production caller needs `convert()` to route hue_pair today —
   spending the first modification-amendment to a GOV-005 file for zero
   current benefit is poor governance economics.
2. Additive placement is semantically honest: `hue_pair` is a different
   coordinate kind (position × hue product), and a separate module makes
   that visible rather than hiding it in a position-frame dispatcher.
3. The audit's wiring plan (Machine-first) will produce a real caller
   inside ~a session of work. If that caller lives in Recursiverse and
   wants `convert()` dispatch, the amendment will have a concrete
   justification and consumer evidence — a much stronger position than
   amending speculatively.
4. If deferred indefinitely is also acceptable, option 3 costs nothing
   and records the decision where future agents will look.

## Trigger to revisit

Any of: (a) a production code path in Recursiverse needing hue_pair
through `convert()`; (b) a second consumer repo requesting canonical
dispatch for contract completeness; (c) a governance review deciding
frame coverage should be total by principle rather than by use.
